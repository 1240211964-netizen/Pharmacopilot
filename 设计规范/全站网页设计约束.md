# 全站网页设计约束

> 本文件用于把 `index首页设计规范.md` 变成其他页面的设计约束。
>
> 结论：`index首页设计规范.md` 是全站页面的视觉母版，其他页面可以根据任务场景做结构变体，但不能脱离它定义的字体、色彩、导航、按钮、教学产品语气和 Artifact 式输出面板气质。

## 1. 强制继承项

所有页面必须继承以下规则。

### 1.1 字体

- 正文、导航、按钮、表单继续使用 `--font-sans`。
- 品牌、大标题、关键输出标题继续使用 `--font-serif` / `--editorial`。
- 等宽字体只用于日志、代码、运行状态，不进入普通正文。
- 默认 `letter-spacing: 0`；只有 eyebrow、小标签、状态标签可以加字距。

### 1.2 色彩

所有页面必须延续首页的暖纸面体系：

- 页面底色：暖纸面，不用纯白冷灰。
- 主文字：深褐黑，不用纯黑。
- 辅助文字：灰褐，不用低对比浅灰。
- 主导航/账户/顶层 CTA：棕色体系。
- 任务推进/执行按钮：鼠尾草绿或灰蓝体系。
- 输出面板：暖白纸面。

禁止把单页改成：

- 纯科技蓝黑风格。
- 紫蓝渐变 SaaS 风格。
- 数据大屏风格。
- 高饱和营销落地页风格。

### 1.3 顶部导航

所有核心页面必须保留四页导航：

- 首页
- 教学导航
- 教学实践
- 教学数据

顶部导航视觉以首页为基准：

- 半透明暖白纸面。
- 16px 左右圆角。
- 紧凑 tab 导航。
- active 状态为浅琥珀底 + 深棕文字。
- 右侧操作按钮为“描边按钮 + 深棕主按钮”的关系。

页面可以根据业务更换右侧按钮文案，但不能换成完全不同的按钮体系。

### 1.4 文字语气

所有页面保持高校教学产品语气。

推荐使用：

- 教学导航
- 教学实践
- 教学数据
- 20 环节训练地图
- 学情分析与学习起点诊断
- 评价量规
- 课后复盘
- 可审校
- 可复用

避免使用：

- 学生画像
- 一键搞定
- 超级神器
- 数据大屏
- AI 全自动替代教师
- 泛 SaaS 增长话术

### 1.5 输出区

凡是承载 AI 生成结果、教学方案、评价结果、数据整理结果的区域，都优先使用首页的 Artifact 式输出面板原则：

- 暖白底。
- 结构化标题。
- 明确可编辑、可预览、可复用动作。
- 内容像可审校文档，而不是聊天气泡或指标堆叠。

## 2. 页面级约束矩阵

### 首页 `index.html`

角色：视觉母版和任务入口。

必须保持：

- 任务发起 + Agent 工作台预览。
- 三功能演示：教学导航 / 教学实践 / 教学数据。
- 居中 hero + 一句话任务输入。
- 白色 Artifact 输出面板。

允许变化：

- 示例课程内容。
- 三功能演示里的具体卡片文本。
- CTA 文案，但必须保持教学产品语气。

### 教学导航 `teaching-navigation.html`

角色：20 环节训练地图与节点解释工作台。

必须继承：

- 顶部导航样式。
- 暖纸面底色。
- serif 大标题。
- 任务地图、节点说明和产出物说明的文档感。
- 关键节点解释区应像审校面板，不像游戏关卡 UI。

允许变体：

- 可以比首页更偏“路线图 / 地图”。
- 可以使用阶段色带、节点状态、路径线。
- 节点卡可以更密集，但仍要有清晰阅读层级。

禁止偏离：

- 不要做成重游戏化地图。
- 不要使用大面积霓虹色或纯深色背景。
- 不要把 20 环节弱化成泛流程图。

### 教学实践 `practice.html`

角色：课堂实践 Copilot / 多智能体运行工作台。

必须继承：

- 首页的“系统正在推进什么过程”表达方式。
- 可见运行状态。
- 关键接管点。
- 右侧或下方 Artifact 式审校输出。
- 顶部导航，不新增左侧主导航替代全站导航。

允许变体：

- 可以比首页更工作台化、更状态化。
- 可以使用运行台、审校面板、事件流、接管按钮。
- 可以使用深色小卡表达 Agent Activity，但输出仍应保持可审校文档感。

禁止偏离：

- 不要做成纯聊天页。
- 不要只放角色对话而没有运行状态和接管点。
- 不要删除旧实践能力，只能折叠或降级。

### 教学数据 `teaching-data.html`

角色：教学材料、生成结果、复盘记录和数据资产的中枢。

必须继承：

- 首页“教学数据”命名。
- 暖纸面底色与白色内容面板。
- 筛选、图谱、人工视图、复用动作的结构化布局。
- 数据卡片仍应有教学语义，而不是通用文件管理器语气。

允许变体：

- 可以更偏列表、表格、筛选器。
- 可以引入图谱/数据视图。
- 可以密度更高，但仍保持充足行高和清晰分区。

禁止偏离：

- 不要恢复为“教学资产”作为可见主名称。
- 不要做成纯网盘/文件列表。
- 不要让数据图谱抢走可读性。

### 登录注册 `auth.html`

角色：低噪声账户入口。

必须继承：

- 首页导航按钮基准。
- Claude-like 的低噪声账户入口。
- 暖纸面、深褐文字、克制按钮。
- 品牌和教学产品语气。

允许变体：

- 可以更简洁。
- 可以使用独立登录卡和说明列。
- 可以提供 provider buttons，但不能喧宾夺主。

禁止偏离：

- 不要做成重营销注册页。
- 不要使用多彩社交登录堆叠破坏整体气质。
- 不要把登录/注册按钮样式改得和首页不一致。

### 工作流、流程图与历史页面

适用页面：

- `workflow.html`
- `flowchart.html`
- `navigation.html`
- `interface-review-improved.html`

必须继承：

- 字体与色彩 token。
- 顶部导航或明确返回核心四页的路径。
- 暖纸面内容区。
- 可读的文档式输出。

允许变体：

- 如果是历史兼容页，可以不完全重构结构。
- 可以保留页面原有功能和 id。
- 优先做视觉约束和术语统一，不强行大改交互。

禁止偏离：

- 不要新增一套独立品牌。
- 不要新增与四页 IA 冲突的主导航。
- 不要用冷色仪表盘替代教学工作台语气。

## 3. 组件继承规则

### 顶部导航组件

后续页面如需重写顶部导航，必须参考首页：

- `.site-header`
- `.topbar`
- `.brand`
- `.topnav`
- `.nav-link`
- `.top-actions`
- `.nav-outline-action`
- `.nav-primary-action`

不能单独为某个页面创造完全不同的登录、注册或主操作按钮。

### Hero / 页面标题

页面标题区应保持：

- 一个清晰 eyebrow。
- 一个 serif 主标题。
- 一个解释真实任务的 lede。
- CTA 不超过两个。

页面不是首页时，标题可以更小、更工作台化，但不要失去 serif + 暖纸面 + 教学任务表达。

### 工作台 / 审校面板

涉及 AI 生成和教学产出的区域，优先拆成：

- 输入材料 / Prompt。
- 系统活动 / 状态。
- 输出预览 / 审校。
- 复用 / 导出 / 下一步。

这比“单聊天框 + 一堆按钮”更符合首页规范。

### 卡片

卡片只用于：

- 重复项。
- 面板。
- 模态框。
- 真正需要框定的工具区。

不要把页面所有 section 都做成套娃卡片。页面大区块应是全宽 band 或无框布局，内部才用卡片。

## 4. 允许的页面差异

不同页面可以在以下方面有差异：

- 信息密度：教学数据可以更密，首页应更疏。
- 状态表达：教学实践可以更强调运行状态。
- 图形表达：教学导航可以使用路径和节点。
- 表单复杂度：登录页可以更少，教学实践可以更多。
- 色彩强调：页面可根据功能使用橙、灰蓝、棕灰三类舞台色。

但差异不能破坏以下识别点：

- 暖纸面。
- 深褐文字。
- serif 标题。
- 棕色主导航。
- 绿蓝执行按钮。
- 白色 Artifact 输出。
- 四页 IA。
- 高校教学语气。

## 5. 设计评审检查清单

每次改其他页面，合并前至少检查：

- 是否仍使用首页定义的字体族？
- 页面底色是否仍是暖纸面体系？
- 顶部导航是否和首页按钮关系一致？
- 页面标题是否是教学任务表达，而不是营销口号？
- AI 生成结果是否进入可审校面板？
- CTA 是否有明确主次？
- 是否保留 `首页 / 教学导航 / 教学实践 / 教学数据`？
- 移动端是否没有文字挤压、按钮溢出、内容重叠？
- 是否避免了数据大屏化、纯聊天化、过度游戏化？

## 6. 后续落地建议

建议分三步落地，不要一次性大改所有页面：

1. 先统一导航、账号按钮、字体、背景和主按钮。
2. 再统一各页面 hero / 标题区 / CTA。
3. 最后把 AI 输出区逐步收敛为 Artifact 式审校面板。

每次只改一个页面或一个组件簇，保留回滚痕迹，避免破坏现有交互绑定。
